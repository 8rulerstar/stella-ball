## 1. 한 줄

**한 화면 위에서 「픽셀 하나」의 물리적 크기가 서로 다르다.** 판에 동시에
놓이는 살아 있는 그림들의 원본 격자를 직접 재 봤다.

| 그림                 | 파일               | 원본 격자       | 화면 표시   | 원본 1픽셀 = 판 위 |
| -------------------- | ------------------ | --------------- | ----------- | ------------------ |
| 별지기 idle          | 1152×192 (6프레임) | 192 (블록 1)    | 93~118px    | **0.48~0.61px**    |
| 별지기 attack 순간   | 768×192            | 192 (블록 1)    | 160~203px   | **0.83~1.06px**    |
| 거상 (boss10)        | 384×384            | 96 (블록 4)     | 184px       | **1.92px**         |
| 유성 (prism-orb)     | 32×32 SVG          | 8 (블록 4)      | 31px        | **3.88px**         |
| 잔재 (void-wisp)     | 1024×256           | 격자 없음       | 96px        | —                  |
| 기믹 (도트 킷)       | 코드               | 셀 2px          | 그대로      | **2px**            |
| HUD 유성 점          | 256×256            | 16 (블록 16)    | 16px        | **1px**            |

| 배경 데코 스프라이트 | 코드               | `px()` 기본 4px | 그대로      | **4px**            |

측정법: 균일 색 런의 최대공약수(`assets/**` 를 Pillow 로 스캔). 표의 어느
줄도 다른 줄과 정수배가 아니다.

그리고 이 전부가 **판 전체의 0.54~0.99배 축소**([BOARD_TEXT](BOARD_TEXT_2026_08_22.md)
§3)를 한 번 더 통과한 뒤, devicePixelRatio 1.5로 **비정수 확대**된다.
「업그레이드」의 첫 항목은 새 그림이 아니라 **이 표를 한 줄로 만드는
결정**이다(§8-1).

같은 문장의 다른 쪽 절반: `assets/` 에 PNG **528장 26.0 MB**가 있는데,
코드가 이름을 부르는 것이 **177장**이고 그중 실제로 화면에 닿는 것은
**130장(약 2 MB)**이다. **바이트의 85%가 한 번도 화면에 닿지 않는다.**

## 3. 집이 정한 도트 규칙

새 그림은 이 규칙 «안에서» 그린다. 여기 적힌 것은 전부 이미 저장소가
스스로 적어 둔 것이지 이 문서가 새로 만든 것이 아니다.

### 3-1. 여덟 규칙 (`stella-ball-dot-gimmicks.js:9-12`)

> 셀 2px · 1셀 외곽선 · 상단 하이라이트 · 5단 밴드 + 체커 디더 · 하드
> 섀도 · 셀 스냅 애니메이션(서브픽셀 이동 없음) · 곡면은 호를 셀로 직접
> 쌓는다(회전 변환 없음) · 캔버스 판정색과 `heroes[].col` 은 건드리지 않는다.

- **셀 스냅**은 `snap(v) = Math.round(v / CELL) * CELL` 한 줄로 강제된다
  (`:34`). 물리에서 온 실수 좌표는 전부 이걸 통과한 뒤에 칠해진다.
- **하드 섀도**는 블러가 아니라 `#04080a` 를 알파 0.5로 4px 내린 사각형이다
  (`:35-41`). DOM 쪽도 같은 색으로 `filter: drop-shadow(0 4px 0 #04080a)`.
- **회전 금지**가 가장 자주 깨지는 규칙이다. 지금 판 위에서 회전이 걸린
  것: 임팩트 FX 세 장(`game-feedback.js:418-466`), 능력 버스트 시트
  (`game-combat.js:1563-1615`), 조준 화면 픽 슬롯
  (`game-combat-physics.js:1704`), 별자리 실루엣(`game-figure.js:958-968`).

(`boss-art.js:10`).

## 6. UI

### 6-1. 구조

한 페이지 · 한 캔버스 · 하나의 `#overlay`다. 모든 메뉴 화면은
`U.over.innerHTML` 교체로 그려진다. CSS는 7장 **10,755줄 244 KB**이고
`!important` 가 **822개**(theme 473 · polish 156 · story 113 · dawn 56 ·
combat 20 · interface 3 · foundation 1)다. `stella-ball-dawn.css`는
테마의 `!important` 버튼 표면을 덮으려고 자기도 `!important`를 쓴다.

픽셀 스킨은 `stella-ball-dawn.js`의 **MAP 5줄**이 셀렉터로 `data-pbtn`을
붙여서 입힌다. 게임 코드에는 `data-pbtn` 이 **0곳**이다(직접 grep).

### 6-2. MAP의 셀렉터 여섯이 죽어 있다

## 7. 한 장으로 보는 우선순위

범위는 정하지 않는다. **순서만** 적고, 각 줄에 그 순서인 이유를 적는다.

1. **§8-1 목표 픽셀 스케일 결정.** 그림 0장. 이것을 정하지 않고 도트를
   찍으면 §4의 1·2·4·7·9번을 두 번 찍는다. 나머지 전부의 선행 조건이다.
2. **§4-5·8 «한 줄» 배율 수정** (거상 `0.48 → 0.5`, 유성 `31 → 32`).
   그림 0장, 코드 두 곳. 1899회·상시 그려지는 두 물건의 격자가 즉시
   맞는다. 결정 1의 답을 미리 시험해 보는 가장 싼 방법이기도 하다.
3. **별지기 8종 다시 찍기 (§4-1·2).** 세션당 4308회로 가장 자주
   그려지고 0.48배로 가장 심하게 축소된다. 이 게임에서 사람이 가장 오래
   보는 그림이다.
4. **범례 아이콘 8종을 도트로 (§5-1).** 코드만. 스스로 「같은 그림이
   두 번 나온다」고 설계 근거를 적어 놓고 실제로는 다른 매체로 그린다 —
   설계 의도와 화면이 어긋난 자리를 코드 한 파일로 메운다.
5. **매끈한 FX 3장 (§4-4).** 화풍이 깨지는 가장 큰 자리이자 바이트가
   가장 큰 자리(1.4 MB)다. 다만 3번보다 뒤인 이유는 «충돌 순간»에만
   보이고 별지기는 «항상» 보이기 때문이다.
6. **UI 평범한 컨트롤 (§6-4).** 슬라이더 셋과 표 둘. 프레임 그림이
   `library/ui/` 에 **이미 있고 미사용**이라 새 도트 없이 절반이 끝난다.
7. **MAP 셀렉터 정리 (§6-2).** 죽은 여섯을 빼고 `.ig-cta` ·
   `.constellation-node` · `.oc-go` 를 넣는다. 파일 한 줄씩이고, 첫
   버튼과 가장 많이 눌리는 버튼이 킷 안으로 들어온다.
8. **잔재 (§4-7).** 판 위 유일한 비도트 적. 3·5번 뒤인 이유는 잔재가
   놓인 판이 34판 중 일부이기 때문이다.
9. **HUD·메뉴 아이콘 재저장 (§4-10~13).** 그림은 그대로 두고 크기만
   맞춘다. 값싸지만 눈에 띄는 변화가 가장 작다.
10. **새 아이콘 세트 (§5-1).** 탭 아이콘 4장, 글리프 8곳, 슬라이더 썸.
    앞의 아홉이 끝난 뒤라야 «어떤 격자로 찍을지»가 정해져 있다.
11. **라이브러리 정리 (§2-2).** 292장을 살릴지 지울지. 마지막인 이유는
    이것이 §8-2의 결정 «이후» 작업이기 때문이다.

### 8-1. 목표 픽셀 스케일 — 이 문서에서 가장 큰 결정

`UI_REVIEW_2026_08_14.md:46` 이 「다른 항목보다 먼저 답이 필요하다」고

스크립트를 지울지가 §4-1의 선행 결정이다.**

## 9. 어떻게 확인하는가

전부 이미 있는 도구다. 새 프로브가 필요한 항목은 없다.

```bash
node scripts/probe-text-size.mjs                 # 판 위 글자 실제 px + 그린 횟수
node scripts/probe-text-size.mjs --sizes 1280,900 1024,680
node scripts/probe-gimmick-stages.mjs            # 월드마다 한 판, 기믹 스크린샷
node scripts/probe-meta-screens.mjs              # 상점·소환·프로필·업적·설정 스크린샷
node scripts/probe-meta-screens.mjs --sizes 1280,900 1024,680
node scripts/probe-window-scale.mjs              # 창을 키우면 무엇이 커지나
node scripts/probe-overdraw.mjs                  # 전면 레이어 장수와 덮는 면적
node scripts/probe-summon.mjs                    # 소환 연출
node scripts/probe-settlement.mjs                # 정산 화면
node bot/run-bot.mjs                             # 회귀 감시 (아트 변경은 diff 0이어야 정상)
npm run check                                    # verify + smoke + 온보딩 E2E
```

| 확인할 것        | 도구                                                | 판정 기준                                                                                                         |
| ---------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| §4-1·2 별지기    | `probe-gimmick-stages` 스크린샷                     | 축소 뒤 1px 외곽선이 구간마다 끊기는가                                                                            |
| §4-5 거상 배율   | 같은 스크린샷                                       | 4px 셀이 정수 픽셀로 떨어지는가                                                                                   |
| §4-4 FX 화풍     | 같은 스크린샷                                       | 충돌 프레임에서 격자가 두 종류로 보이는가                                                                         |
| §5-1 범례 아이콘 | 같은 스크린샷                                       | 범례 아이콘과 판 위 물건이 같은 재질로 읽히는가                                                                   |
| §6 UI 스킨       | `probe-meta-screens`                                | 화면마다 픽셀 버튼과 CSS 버튼이 섞여 있는가                                                                       |
| §6-5 HUD         | `probe-meta-screens --sizes … 1024,680`             | 760px 아래에서 사라지는 카드                                                                                      |
| §8-1 픽셀 스케일 | `probe-window-scale` + `probe-text-size`            | 창을 바꿔도 격자가 유지되는가                                                                                     |
| 성능             | `probe-overdraw`, `node scripts/profile-frames.mjs` | 새 시트가 프레임 예산을 넘기는가                                                                                  |
| 결정론           | `node bot/run-bot.mjs`                              | **`bot/latest-report.json` 이 안 움직여야 한다.** 표현 계층 변경이 이 파일을 움직이면 그것은 규칙을 건드린 것이다 |
| 서식             | `npm run format`                                    | 반드시 `npm run format`. 맨 `npx prettier`는 3.9.6이 돌아 한국어 범위 표기 `10~11px`를 `10~~11px`로 망친다        |

반입 뒤에는 `ASSET_PLAN.md` 와 `assets/ASSET_MANIFEST.json` 에 출처·경로를
기록하고 백로그 항목을 `반입 완료`로 옮긴다(`AGENTS.md:155`). 다만
매니페스트는 지금 528장 중 104장만 선언하고 있고 게임이 아니라
`scripts/verify-evidence.mjs` 만 읽는다 — **매니페스트와 디스크와 코드
