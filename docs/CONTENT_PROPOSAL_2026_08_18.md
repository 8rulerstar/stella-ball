## 1. 밸런스 — 순서를 바꿔야 한다

### 측정

- 34개 스테이지의 체력이 봇 중앙 피해 용량의 **0.22~0.77배**다. 봇은 필요한 것의 1.3~4.5배를 때린다. (`BOT_REPORT.md` 0-4)
- 유일한 예외가 8-1로 **2.43배**, 실측 클리어율 **2.1%**. 다음으로 어려운 7-1이 60.4%다.
- 클리어율 100%인 스테이지가 **4개** 있다.
- 배치는 `CAMPAIGN_LAYOUTS[i % 7]`로 7종이 순환하고 체력만 120 → 380으로 선형 증가한다. **두 곡선은 서로를 모른다.**

### 왜 지금 체력을 다시 깎으면 안 되는가

같은 날 0-7절에서 잰 것: **한 발 안에서는 조준이 읽히지만(0.25°가 피해를 13~25% 바꾼다), 둘째 발부터 결과가 첫 발의 우연에 지배된다**(같은 간격에서 변동이 15배로 뛴다). 그래서 5발 합계의 p10~p90이 1-1에서 237~1029, **4.3배**로 벌어진다.

체력을 어디에 맞추든 그 값은 **운이 지배하는 띠 안에** 놓인다. 띠를 좁히지 않고 체력만 맞추면 요동을 그대로 굳힌다.

### 제안 (택일)

| 안                                 | 내용                                                                                                                              | 대가                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **A. 띠부터 좁힌다**               | 5발 합계의 분산을 줄이는 규칙을 먼저 넣는다(예: 샷마다 최소 보장 피해, 또는 발당 정산을 독립시켜 첫 발의 우연이 뒤로 번지지 않게) | 설계 변경이라 가장 크다. 대신 이후 모든 밸런스 작업이 의미를 갖는다 |
| **B. 띠를 인정하고 목표만 정한다** | 목표 클리어율을 정하고 체력을 배치별 용량 × 목표 배수로 다시 잡는다                                                               | 싸다. 다만 「실력이 아니라 운으로 갈린다」는 성질은 남는다          |
| **C. 8-1 절벽만 손본다**           | 34개는 두고 2.43배만 낮춘다                                                                                                       | 가장 싸다. 평지 34개 문제는 그대로                                  |

**추천: A → B 순서.** C는 증상만 가린다.

### 8-1 (별도 판단)

봇 최고 기록이 1328/1600(83%)이라 도달 불가능하지는 않다. **34개가 0.22~0.77배인 곡선 끝에 붙은 절벽**을 의도로 둘 것인지가 결정 사항이다.

## 2. 아이템 — 자리는 이미 파여 있고 비어 있다

### 측정

`build`는 다섯 필드를 가진다.

```js
build = {
  weakFlat: 0,
  chainStep: 0,
  extraShots: 0,
  bounceStep: 0,
  markMultiplier: 1.7,
};
```

피해 계산식이 이 값을 실제로 읽는다 — `RULES.baseDamage + build.weakFlat`, `amount *= build.markMultiplier`, `1 + (chain.length - 1) * (RULES.chainStep + build.chainStep)`.

그런데 **런타임 전체에서 이 값을 올리는 코드가 한 줄도 없다.** `resetBuild()`가 유일한 기록자다. 넷은 영구히 0이고, `markMultiplier`만 1.7 상수로 동작한다.

### 뜻

전투 중 성장이 **없다.** 그리고 그 성장을 받을 배선은 이미 피해식 안에 들어 있다. 새 시스템을 만드는 것이 아니라 **비어 있는 다섯 칸을 채우는 일**이다.

### 제안

스테이지 클리어 사이에 세 장 중 하나를 고르게 한다(로그라이크식). 각 카드는 위 필드 하나를 올린다.

| 필드             | 카드 예시                    | 무엇을 바꾸나                                        |
| ---------------- | ---------------------------- | ---------------------------------------------------- |
| `weakFlat`       | 「무딘 별동별」 직격 피해 +N | 조준이 나쁜 판을 구제                                |
| `chainStep`      | 「연쇄 각인」 연쇄 배수 +N   | 별지기 경유를 보상                                   |
| `bounceStep`     | 「반사 각인」 벽 반사 보너스 | 벽 기믹이 들어와야 의미가 생김(3절과 묶임)           |
| `extraShots`     | 「여분의 유성」 발수 +1      | **띠를 넓히므로 1절 A안과 충돌한다 — 마지막에 검토** |
| `markMultiplier` | 「표식 심화」 표식 배수 +0.3 | 지금 유일하게 살아 있는 값                           |

**주의**: `extraShots`는 5발 합계의 분산을 더 키운다. 1절에서 A를 고르면 이 카드는 빼거나 마지막에 다시 본다.

## 3. 기믹 — 만든 것을 연결하는 일

### 측정

벽·발판·잡몹은 `setupStageGimmicks()`가 스테이지 선언에서 생성한다. 캠페인 사용 **0**. `LEGACY_GIMMICK_STAGES`의 12개 스테이지 정의가 쓰이지 않고 남아 있다.

### 제안

`MAINTENANCE.md`가 이미 규칙을 정해 뒀다 — **새 기믹을 소개하는 스테이지에는 그 기믹만 두고, 그 외에도 최대 두 종류까지.** 그 규칙대로 월드별로 하나씩 배정한다.

| 월드             | 도입 기믹     | 이유                                                                         |
| ---------------- | ------------- | ---------------------------------------------------------------------------- |
| 양자리 (3)       | 없음          | 튜토리얼 월드. 지금 그대로                                                   |
| 화살자리 (4)     | **벽**        | 「발사 뒤 궤도 전환」이 월드 주제다. 반사면이 그 주제를 판 위에 세운다       |
| 까마귀자리 (4)   | **가속 발판** | 「충돌 순서와 다음 샷의 자리를 읽는다」 — 속도를 바꾸는 지형이 순서를 바꾼다 |
| 카시오페이아 (5) | 벽 + 발판     | 두 종류 조합의 첫 스테이지                                                   |
| 백조자리 (5)     | **잡몹**      | 표적이 여럿이면 별자리 접점이 늘어난다                                       |
| 오리온 (6)       | 잡몹 + 벽     |                                                                              |
| 큰곰자리 (7)     | 전부          | 마지막 월드                                                                  |
| 바깥 (1)         | 페이즈        | 지금 그대로                                                                  |

**밸런스 영향은 반드시 재측정해야 한다.** 기믹은 피해 용량을 바꾸므로 0-4절의 표가 무효가 된다. 하니스에 기믹 스테이지를 태우는 것은 이미 가능하다(`runCampaignStage`가 스테이지 선언을 그대로 쓴다).

## 4. 페이즈 연출 — 둘은 구현돼 있고 캠페인에서는 하나도 안 쓰인다

### 측정

`runStagePhase(effect)`에 구현된 효과는 **둘**이다.

- `push` — 거상의 포효. 판 위의 모든 것을 가장 가까운 모서리로 **실제로 밀어 보낸다**(0.12초 뒤 출발, 0.46초에 도착). 순간이동이 아니다
- `sleep` — 별지기가 다시 잠들고, `wakeNeed`회 충돌해야 깨어난다

캠페인에서 페이즈를 선언한 스테이지는 8-1 하나인데, 그 효과는 `"form"`이다. **`runStagePhase`가 모르는 값이며 이것은 의도된 것이다** — 코드 주석이 그렇게 적고 있다. 전투 룰에는 아무 영향이 없고 `stagePhases.fired`만 올라가 보스 아트의 페이즈 인자가 된다.

**즉 전투 규칙을 바꾸는 페이즈를 가진 캠페인 스테이지는 현재 0개다.** `push`와 `sleep`은 구현돼 있고, 그것을 쓰는 정의는 `LEGACY_GIMMICK_STAGES`에 둘 남아 있지만 연결돼 있지 않다.

### 제안

**월드 보스에게 페이즈 하나씩.** 지금은 모든 스테이지가 같은 방식으로 끝난다 — 체력이 0이 되면 이긴다.

| 페이즈              | 언제           | 무엇이 바뀌나                                                                                 |
| ------------------- | -------------- | --------------------------------------------------------------------------------------------- |
| `push` (있음)       | 체력 66% / 33% | 짜 놓은 항로가 무너진다. 다시 짜야 한다                                                       |
| `sleep` (있음)      | 체력 50%       | 별지기를 다시 깨워야 해서 발을 소모한다                                                       |
| `shell` (신규 제안) | 체력 40%       | 굳은 껍질이 생겨 직격이 통하지 않는다 — **별자리로만 깎인다.** 간판 기믹을 결말에 쓰게 만든다 |
| `split` (신규 제안) | 체력 30%       | 보스가 잡몹 둘을 분리한다. 3절의 잡몹 기믹을 재사용                                           |

`shell`은 특히 값이 크다. 지금 별자리는 **있으면 좋은 것**이지 **써야 하는 것**이 아니다 — 0-6절에서 `contact` 정책이 별자리를 우연히 터뜨리다 말았는데도 클리어율이 거의 안 변한 이유가 그것이다(별자리가 피해 예산에서 차지하는 비중이 작다).

### 주의

페이즈는 히트스톱과 화면 흔들림을 부른다. 같은 날 측정으로 **단일 최대 정지 115ms, 정지 사이 간격 중앙값 261프레임(4.4초)**이다. 페이즈를 늘리면 이 간격이 좁아진다. 6프레임 이내로 몰리기 시작하면 그때는 피니셔처럼 **발수로 나누는 처리**가 필요하다 — 지금은 몰리지 않아서 불필요하다.

## 5. 하니스가 아직 못 재는 것

제안을 실행하기 전에 알아야 할 계측 한계다.

- **기본 스윕은 조준 보정을 거치지 않는다.** `aimPath: true`를 켜야 사람과 같은 경로다. 켜지 않고 잰 수치가 안 변했다면 그것은 「안 변했다」가 아니라 「측정되지 않았다」이다
- **`precise` 버킷은 표본이 아니다.** σ=0이면 시드가 무력해 서로 다른 판이 35개뿐이다(리포트가 이제 `distinctRuns`로 함께 낸다)
- **아이템·기믹을 넣으면 0-4절의 피해 용량 표가 전부 무효가 된다.** 같은 커밋에서 다시 재야 한다
