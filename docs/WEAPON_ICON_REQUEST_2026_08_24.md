# 디자인 요구서 — 별무기 아이콘 12종 (글리프 → 도트)

> 작성 2026-08-24 · 오너 지시 「무기 에셋 요청서 써줘」
>
> 배경: 이날 별무기 시스템과 무기 뽑기를 넣었다(커밋 `d1d4e95`). 무기
> 아이콘은 **임시 글리프**(⚔🗡🌌…)로 세워 두었다. 이 요구서는 그 글리프를
> 대신할 **도트 아이콘 12장**을 청한다.
>
> 재현: 게임 → 허브 → «소환» 탭 → 상단 세그먼트 «무기»(소환 후보 12칸)와
> «무기고»(별지기별 장착 칸). 두 화면과 소환 연출 카드가 아이콘이 뜨는 자리다.

## 1. 한 줄

**열두 자루가 전부 유니코드 글리프다.** 검(⚔)·활(🏹)은 그럭저럭이지만
프리즘(✨)·회오리(🌀)·거울(🌑)은 무기로 안 읽히고, OS·폰트마다 모양이 갈려
«등급»도 «임자»도 그림이 말하지 않는다. 각자 다른 한 자루로 읽히는 도트가
필요하다.

## 2. 지금 상태 — 실측

아이콘은 `.weapon-ico` 한 클래스로 다섯 자리에 뜬다. **가장 작게 28px,
가장 크게 62px.** 도트는 이 구간에서 읽혀야 한다.

| 자리                    | 상자    | 지금 글리프 크기 | 어디서                   |
| ----------------------- | ------- | ---------------- | ------------------------ |
| 소환 연출 카드          | 62×62px | 34px             | `weaponRevealMarkup()`   |
| 무기 소환 후보(풀)      | 34×34px | 18px             | `showWeaponGacha()`      |
| (일반 `.weapon-ico`)    | 40×40px | 22px             | 공통                     |
| 무기고 · 장착된 무기    | 30×30px | 16px             | `armoryHeroRow()`        |
| 무기고 · 무기 고르기 칩 | 28×28px | 15px             | `armoryHeroRow()` picker |

등급은 **상자(프레임)**가 색으로 말한다. 이건 이미 CSS에 있으니 **아이콘 그림이
등급색을 칠할 필요가 없다** — 오히려 칠하면 프레임과 겹쳐 탁해진다.

| 등급           | 프레임(이미 구현)                                                |
| -------------- | ---------------------------------------------------------------- |
| 일반 common    | 테두리 `#4a5a6d`, 차가운 은빛 상자 `#24313f→#0d141c`             |
| 전용 exclusive | 테두리 `#a5772f`, 금빛 상자 `#4a3413→#1c1206` + 글로우 `#ffcf7a` |

## 3. 요청 — 아이콘 12장

로스터는 §부록 A의 12자루다. 요청은 셋이다.

### 3-1. 한 자루로 읽히는 실루엣 (최우선)

28px에서 **무엇인지** 읽혀야 한다. 검은 검, 활은 활, 망치는 망치. 프리즘·
거울·회오리처럼 형태가 애매한 것은 «무기/도구»의 골격을 잡아 준다 —
프리즘은 쌍성을 가르는 삼각 결정, 거울은 자루 달린 손거울, 부채는 접힌
물비늘 부채. 정하지 않은 것은 §부록 A의 «형태 힌트»를 출발점으로 삼되
디자인 판단으로 바꿔도 된다.

### 3-2. 일반 4 · 전용 8이 «등급»으로 갈려 보이게

프레임이 이미 은/금으로 가르지만, 아이콘 자체도 격이 달라야 한다. **전용은
한 끗 화려하게** — 룬 각인, 흐르는 광채, 별빛 파티클 한둘. 일반은 담백한
도구. 나란히 놓았을 때 «이건 특별한 물건»이 읽히면 된다.

### 3-3. 전용 8자루는 «임자»의 색을 두른다

전용 무기는 특정 별지기 전용이다(§부록 A의 «임자·고유색»). 그 별지기의
고유색을 아이콘에 **한 조각** 넣어 준다 — 여명파검엔 샛별의 살구금, 은하
시위엔 미리내의 분홍. 무기고에서 «이 무기는 저 별지기 것»이 색으로 이어지면,
전용 발동(+70%)의 짝이 그림으로 읽힌다. **주(主)는 무기의 재질, 별지기색은
악센트**다 — 통째로 칠하지 말 것.

## 4. 규격 — 두 경로 중 택일

이 저장소엔 도트 아이콘 체계가 **둘** 있고, 무기 아이콘은 어느 쪽으로 와도
붙는다. **권하는 쪽은 A(절차적 맵)**다 — 허브 탭 아이콘과 같은 길이고, 바이너리
파일이 늘지 않으며, 되돌리기가 코드 한 줄이다.

### 경로 A — 절차적 픽셀맵 (권장)

허브 탭 다섯이 이미 이 방식이다(`stella-ball-pixel-ui.js`의 `MAPS`,
`stella-ball-upgrade.js`의 `tabIcons()`). **문자열 행 + 팔레트**로 그린다.

```js
// stella-ball-pixel-ui.js 의 MAPS 에 더한다. 렌더러 px(rows, pal, s):
//   각 글자를 s×s 블록으로 칠하고 dataURL 반환. 팔레트는 글자→hex, '.'=투명.
MAPS.wpnStardustBlade = [
  [
    /* 16×16 권장 (탭은 8×8이지만 62px까지 커지므로 한 단계 크게) */
  ],
  { s: "#cfe0ee", h: "#8fb7d6", e: "#3a4a5c", k: "#0b0f14" }, // 예: 칼날/자루/외곽/그림자
];
```

- **격자: 16×16 권장** (24×24까지 허용). 탭의 8×8은 62px에서 뭉갠다.
- **팔레트: 자유 키.** `.`(온점)은 투명. 외곽선 한 겹으로 상자 배경과 분리.
- **알파는 0/255** — 반투명 없음(도트 규칙).
- 12개 맵의 이름은 `wpn<Id>`(§부록 A의 id를 PascalCase). 코드가 그 이름으로 집는다.

### 경로 B — PNG 파일

`assets/library/icons/weapon/<id>.png`. **한 변 64px, 16×16 논리(4× 확대)**,
투명 배경, `image-rendering: pixelated`로 얹는다. 기존 `assets/library/icons/`
(star-8/16/24/32, upgrade-\*.png)와 같은 폴더 관례다.

## 5. 지켜야 하는 것

- **예약색 금지.** 살구 램프(오리온 보스)·안내별 금·CTA 금·경고 적색은 아이콘
  안에 쓰지 않는다. 전용 등급의 «금빛»은 **프레임이** 이미 낸다 — 아이콘까지
  같은 금을 크게 칠하면 CTA 금과 충돌한다. 전용 아이콘의 금속감은 **은은한
  하이라이트**로, 등급 신호는 프레임에 맡긴다.
- **별지기 고유색은 악센트 한 조각**(§3-3). 통째로 칠하면 «임자» 신호가 아니라
  그냥 그 색 무기가 된다. 특히 달무리(`#bca7ff`)와 그믐(`#9f83ff`)은 hue가
  0.8° 차이라 아이콘에서 구분이 안 되니, **색이 아니라 형태**(고리 vs 거울)로
  가른다.
- **28px가 기준선**이다. 62px에서 예쁜데 28px에서 뭉치면 반려다 — 무기고
  고르기 칩이 28px다.
- **성능·계약.** 경로 A는 dataURL 캐시라 프레임 비용이 사실상 0이고 바이너리가
  안 는다. 경로 B는 12장이 `assets/library/icons/weapon/`에 들어가고, 이식성
  게이트(`check-portability.mjs`)가 참조 경로의 git 추적을 검사하므로 **반드시
  커밋에 포함**한다(오디오에서 이걸로 한 번 걸렸다).

## 6. 검수

- [ ] 12자루가 28px에서 각각 «무엇인지» 읽히는가 (프리즘·거울·부채 포함)
- [ ] 일반 4와 전용 8이 아이콘만 봐도 격이 갈리는가 (§3-2)
- [ ] 전용 8이 임자의 고유색을 «한 조각» 두르는가 — 통째 칠은 아닌가 (§3-3)
- [ ] 달무리 고리와 그믐 거울이 형태로 구분되는가 (색으론 못 가른다)
- [ ] 아이콘이 등급 금/은을 크게 칠해 프레임과 충돌하지 않는가 (§5)
- [ ] (경로 B면) 12장이 커밋에 포함됐는가 — 이식성 게이트

## 7. 코드 연결 지점

아트만 오면 **코드 배선은 내(윈도우)가** 한다. 지금 `.weapon-ico`는 글리프를
텍스트로 담고 있어, `data-weapon="<id>"` 속성을 붙이고 허브 탭과 같은 스왑
패스로 교체하면 된다.

- `prototypes/js/game-meta.js`
  - `weaponRevealMarkup()` · `showWeaponGacha()` · `armoryHeroRow()` — 세 곳이
    `<i class="weapon-ico grade-…">글리프</i>`를 찍는다. 여기에 `data-weapon`을 단다.
- `prototypes/stella-ball-pixel-ui.js` — 경로 A면 `MAPS`에 `wpn*` 12개 추가.
- `prototypes/stella-ball-upgrade.js` — `tabIcons()` 옆에 `weaponIcons()` 패스를
  더해 `[data-weapon]`의 글리프를 도트 `<img>`로 교체(탭 아이콘과 동일 패턴).
- `prototypes/stella-ball-upgrade.css` — `.weapon-ico img{image-rendering:pixelated}`.
- 되돌리기: 스왑 패스 한 줄(또는 `<script>` 한 줄)을 빼면 글리프로 돌아간다.
  아트를 지울 필요가 없다.

## 부록 B — 왜 «형태로 구분»을 두 번 말하나

로스터 팔레트에서 **달무리(hue 254.3°)와 그믐(hue 253.5°)이 0.8° 차이**라
색으론 사실상 같다(각성 이펙트 시트에서도 같은 한계가 있다). 그래서 이 둘의
전용 무기 — 달무리 고리 ⭕ 와 그믐 거울 🌑 — 는 **색이 아니라 형태**로 갈려야
한다: 하나는 뚫린 고리, 하나는 자루 달린 거울. 색 악센트는 거들 뿐이다.
