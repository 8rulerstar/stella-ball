## 1. 한 줄

**시전 8장이 서로 잘 안 갈린다.** 28쌍 가운데 10쌍이 실루엣으로 구분되지
않는다(36%). 대체한 예전 세트는 21쌍 중 3쌍이었다(14%). 색을 빼고 형태만 보면
윤슬·모루·달무리·그믐·샛별이 서로 비슷한 덩어리다.

**각성 8장과 정산 타격 8장은 문제가 없다. 그대로 쓴다.**

## 2. 실측 — 이 요구서의 근거

### 2-1. 재는 법과, 처음에 잘못 잰 것

색으로 재면 안 된다. 여덟은 이미 고유색으로 갈려 있고 달무리(`#bca7ff`)와
그믐(`#9f83ff`)은 hue 0.8° 차이라 색이 아예 못 가른다. 그래서 **알파 실루엣만**
논리 24×24 로 뽑아 쌍마다 IoU 를 낸다. 도구는 `scripts/measure_fx_distinctness.py`.

두 가지를 조심해야 한다. 둘 다 처음에 틀렸던 자리다.

- **한 프레임이 아니라 네 프레임을 합쳐야 한다.** 처음에는 가장 꽉 찬 프레임
  하나만 봤는데, 각성 시트에서 그 방법이 **틀린 답**을 냈다 — 여덟이 공유하는
  고리가 그 프레임의 픽셀 대부분이라 IoU 0.78 이 나왔고, 정작 갈리는 2·3프레임의
  솟는 표식(검·활·혜성·칼날바퀴·모루·구슬)이 묻혔다. 멀쩡한 시트를 결함으로
  보고할 뻔했다.
- **세트 전부에 공통인 칸은 빼고 재야 한다.** 그것은 그 세트의 «어휘»이지
  구분을 방해하는 것이 아니다. 각성 시트는 44%가 공유 어휘(고리 + 반짝임
  사슬)이고, 그것을 빼면 중앙 IoU 가 0.83 → 0.32 로 떨어진다.

### 2-2. 세 세트 비교 (같은 방법, 공유 어휘 제거 후)

| 세트                     | 공유 어휘 | 중앙 IoU | 최악                 | 0.45 이상 쌍      |
| ------------------------ | --------: | -------: | -------------------- | ----------------- |
| **시전 8장 (새)**        |        4% | **0.36** | 0.72 (윤슬↔모루)    | **10 / 28 (36%)** |
| 각성 8장 (새)            |       44% |     0.32 | 0.64 (샛별↔미리내)  | 4 / 28 (14%)      |
| 예전 per-kind 7장 (기준) |        2% |     0.35 | 0.70 (seek↔copycat) | 3 / 21 (14%)      |

**중앙값은 예전과 비슷하다. 늘어난 것은 «구분 안 되는 쌍의 비율»이다 — 14% →
36%.** 각성 세트가 공유 어휘 44%를 쓰고도 14%인 것과 대조된다: 어휘를 공유하는
것은 괜찮고, 표식이 안 갈리는 것이 문제다.

### 2-3. 구분되지 않는 여덟 쌍

| 쌍             |  IoU |     | 쌍             |  IoU |
| -------------- | ---: | --- | -------------- | ---: |
| 윤슬 ↔ 모루   | 0.72 |     | 샛별 ↔ 윤슬   | 0.50 |
| 윤슬 ↔ 달무리 | 0.57 |     | 샛별 ↔ 모루   | 0.49 |
| 모루 ↔ 그믐   | 0.54 |     | 미리내 ↔ 살별 | 0.47 |
| 윤슬 ↔ 그믐   | 0.53 |     | 달무리 ↔ 모루 | 0.46 |

읽는 법 둘.

1. **윤슬이 네 쌍에 등장한다** — 모루·달무리·그믐·샛별 전부와 겹친다. 회전
   칼날이 «가운데가 찬 둥근 덩어리»라 다른 둥근 것들과 구별되지 않는다.
2. **미리내 ↔ 살별은 방향이 같아서 겹친다.** 저격과 중계가 둘 다 가로로 뻗는
   화살이다. 색만 분홍·초록이 다르다.

### 2-4. 배선은 정상이다 (헛짚지 않기 위해)

세 가지를 확인했으니 다시 의심하지 않아도 된다.

- 런타임이 샛별에 대해 실제로 `gaon-swordwave.png` 를 집는다. 시트 OFF/ON 을
  같은 판·같은 프레임에서 찍어 비교하면 새 것이 더 굵고 블록지게 보인다.
- 크기 문제가 아니다. 프레임 하나가 칠해진 비율이 샛별 29.3% 대 예전 23.1%,
  달무리 25.9% 대 12.6% 로 **오히려 커졌다.**
- 「옛 자산이 270~340px 로 함께 그려져 새 시트를 묻는 것」이 아니다. 그
  그리기(`game-feedback.js` 의 `paintFeedbackAsset(abilityFx[gate.id], …)`)는
  **도달 불가 코드**다 — `game-awaken-fx.js` 가 `drawFinisherFocus` 를 통째로
  갈아 끼우고 그쪽은 옛 벡터를 그리지 않는다.

## 3. 요청 — 능력이 그림에서 갈리게

같은 어휘를 색만 달리해 여덟 번 그리는 대신, **그 별지기가 실제로 하는 일**이
실루엣에서 읽히게 해 달라. 아래는 코드가 정말로 도는 것이다(추측이 아니라
`game-combat-physics.js` 의 정산 분기와 `game-combat.js` 의 능력 함수다).

| 별지기        | `fx`         | 코드가 하는 일                                        | 지금 그림   |
| ------------- | ------------ | ----------------------------------------------------- | ----------- |
| 샛별 gaon     | `slash`      | 근접 베기. **사거리 밖에도 닿되 가까울수록 강하다**   | 초승달      |
| 미리내 biyeon | `longshot`   | 거리 저격. 멀수록 유리한 유일한 능력                  | 화살        |
| 별하 lumi     | `split`      | 유성을 **둘로 쪼갠다**(`ball.splitUsed`)              | 갈라진 고리 |
| 살별 haru     | `seek`       | 가장 가까운 별지기로 **강제 중계** — 목표를 «옮긴다»  | 혜성        |
| 윤슬 ria      | `bladewheel` | 이동 속도에 비례하는 회전 칼날 + **보스·별지기 관통** | 3날 바퀴    |
| 달무리 sera   | `turn`       | **정산 구현이 없다** — 4절을 볼 것                    | 궤도        |
| 모루 taeo     | `shockwave`  | 충돌 수에 비례하는 충격파. 여덟 중 가장 넓다          | 파문        |
| 그믐 nyx      | `copycat`    | 마지막에 부딪힌 아군의 능력을 **모사**                | 사각 겹침   |

원하는 것은 「더 화려하게」가 아니라 **여덟이 서로 다른 형태**다. 판에 셋이
동시에 정산할 때 누가 무엇을 했는지 색을 보지 않고도 읽히면 된다.

방향 힌트 넷(정하지 않았다):

- **선 대 면.** 베기·저격은 선이고 충격파·분열은 면이다. 지금은 여덟이 다 «면»에
  가깝다.
- **닫힘 대 열림.** 관통(윤슬)과 중계(살별)는 «지나간다» — 끝이 열려야 한다.
  포위·충격파는 닫혀야 한다.
- **개수.** 분열은 둘, 삼연격은 셋, 모사는 겹친 둘. 개수가 곧 뜻인 능력이 있다.
- **방향.** 저격·중계·베기는 방향이 있고 충격파·회전은 없다. 지금은 전부
  → 기준으로 그려져 있는데, 방향 없는 것에 방향을 주면 회전이 어색해진다.

## 4. 달무리 문제 — 그릴 것이 정해지지 않았다

**여덟 중 유일하게 정산 구현이 없다.** `game-combat-physics.js` 의 정산 분기에
`slash`·`longshot`·`shockwave`·`bladewheel`·`copycat` 은 있고 `turn` 은 없다.
`ASSET_PLAN.md` 의 「유닛 전용 이펙트」 표도 달무리 칸에 「다음 발동 규칙 설계 후
연결 예정」이라고 적어 두었고, `PROJECT_CONTEXT.md` 는 「달무리는 현재 기본
공명으로 함께 가속하며 별도의 고유 공격은 없다」다.

그래서 `sera-orbit.png` 는 **없는 능력의 그림**이다. 셋 중 하나가 필요하다.

1. 규칙을 먼저 정한다(오너 결정) — 그 뒤에 그린다.
2. 「함께 가속한다」를 그대로 그린다 — 공명 가속이 달무리의 능력이므로, 미는
   힘·같이 굴러가는 궤적처럼.
3. 이번 배치에서 빼고 per-kind `fx-turn-burst` 를 그대로 쓴다.

## 5. 규격 — 이건 바꾸지 말 것

돌아온 24장의 규격은 정확했다. **같은 규격을 지켜 달라.**

| 항목      | 값                                                    |
| --------- | ----------------------------------------------------- |
| 시트      | 768×192, 가로 4프레임                                 |
| 프레임    | 192×192                                               |
| 셀        | 8px → **논리 해상도 24×24**                           |
| 알파      | 0 또는 255 (반투명 없음)                              |
| 화면 크기 | 약 193px 로 그려진다 — 192 프레임이 거의 **1:1** 이다 |

**논리 24×24 가 이 요청의 진짜 제약이다.** 실루엣을 가르는 일이 24칸 안에서
끝나야 한다. 대체한 기존 시트들은 프레임이 256×256 이었고 193px 로 축소돼
그려졌다 — 지금 규격이 더 낫다. **크게 만들어 해결하려 하지 말 것.**

### 색

- 각 별지기 고유색 5단 + 외곽선. 돌아온 24장이 이 규칙을 정확히 지켰다
  (중앙 hue 가 고유색과 0.0~17.6° 차이).
- **팔레트 규칙**(`CLAUDE.md` §1-1, §1-4). 금은 **보상·CTA·별자리**의 색이고,
  마젠타(`--magenta`)는 **바깥 관측자와 하늘 이상**의 색이다. 둘을 섞지 않으며,
  별지기 고유색과 유성·바닥의 판정색은 연출이 덮지 않는다.
- 그래서 아래 색들은 이미 다른 것을 뜻하고 있으니 비켜 달라. 돌아온 24장이
  전부 비켜 갔으므로(전수 검사, 침범 0장) 그 수준을 유지한다는 뜻이다.

  | 색        | 지금 뜻하는 것               |
  | --------- | ---------------------------- |
  | `#ffd2a0` | 살구 램프 — 오리온(6점) 전용 |
  | `#ffd27f` | 안내별 · 판 위 별빛          |
  | `#f2b35c` | CTA 금                       |
  | `#ff5a4d` | 경고 · 음소거 사선           |
  | `#fff6e6` | 북두칠성 은하수의 밝은 별    |

  샛별(`#f2c56b`)만 고유색 자체가 금 계열이다 — 그건 그 별지기의 색이므로
  그대로 쓴다.

- 고유색은 아래 여덟이다.

| 샛별      | 미리내    | 별하      | 살별      | 윤슬      | 달무리    | 모루      | 그믐      |
| --------- | --------- | --------- | --------- | --------- | --------- | --------- | --------- |
| `#f2c56b` | `#ef718d` | `#70dce1` | `#9ee477` | `#5fe0cf` | `#bca7ff` | `#ffac67` | `#9f83ff` |

### 달무리·그믐이 같은 색이다

```
달무리 #bca7ff  hue 254.3
그믐   #9f83ff  hue 253.5    ← 0.8° 차이
```

시트가 아니라 로스터 팔레트의 충돌이라 이번에도 색으로는 못 가른다. **그 둘은
형태로만 갈릴 수 있다** — 이 요청이 그 둘에게 특히 중요한 이유다.
