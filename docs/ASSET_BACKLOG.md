# Stella Ball — 디자인·에셋 제작 백로그

> 기능 구현 중 발견한 시각 자산 요구를 잃지 않고 모으는 단일 장부다.
> **이 문서는 제작 목록이지, 즉시 제작 지시가 아니다.** 새 아트·애니메이션·SFX는 사람이 일괄 제작 패스를 승인한 뒤에만 반입한다.

## 작업 규칙

1. 기능 작업에서 새 시각 자산이 필요해 보이면, 먼저 이 문서에 항목을 추가한다. 새 PNG·GIF·WAV를 임의로 만들거나 외부 에셋을 바로 반입하지 않는다.
2. 현재 파일·CSS 도형·기존 라이브러리로 플레이 가능성을 유지할 수 있으면 임시 표현을 사용하고, 최종 자산 요구는 여기에 남긴다.
3. 항목에는 **무엇을**, **어디에서**, **어떤 플레이 피드백을 위해** 쓰는지 적는다. 단순히 “멋진 이펙트”처럼 목적이 없는 항목은 등록하지 않는다.
4. 프레임 수·해상도·팔레트·출처는 알 때만 적고, 모르는 값은 추정하지 않는다. `미정`으로 둔 뒤 일괄 아트 패스에서 결정한다.
5. `제작 준비`가 된 항목만 다음 에셋 작업의 입력이다. 제작 후에는 원본·라이선스·경로를 `ASSET_PLAN.md`와 `assets/ASSET_MANIFEST.json`에 기록하고, 이 장부는 `반입 완료`로 옮긴다.
6. 게임 규칙·수치가 바뀌어 필요가 사라지면 삭제하지 말고 `보류/폐기`와 이유를 남긴다. 나중에 같은 아이디어를 되살릴 근거가 된다.

## 상태와 우선순위

| 상태        | 뜻                                              |
| ----------- | ----------------------------------------------- |
| `후보`      | 기능 구현 중 발견. 아직 제작하지 않는다.        |
| `명세 필요` | 역할은 확정됐지만 형태·규격·출처가 부족하다.    |
| `제작 준비` | 일괄 아트 패스에 넣어도 되는 명세다.            |
| `반입 완료` | 파일·출처·실제 사용 경로가 확정됐다.            |
| `보류/폐기` | 현재 범위에서는 만들지 않는다. 이유를 보존한다. |

- `P0`: 없으면 조작·피드백·가독성이 깨진다. 다만 즉시 제작하지 말고 최소 임시 표현을 쓴다.
- `P1`: 전투나 화면의 핵심 정체성을 강화한다. 다음 일괄 패스 후보다.
- `P2`: 품질을 높이지만 현재 플레이에는 영향이 없다.

### [명세 필요] P1 — 보스별 발동 SFX 구분

- 화면 / 트리거: 보스 10종의 attack·death 프레임.
- 플레이 목적: 실루엣과 색은 구분되지만 소리가 공용 큐라, 어떤 보스의 어떤 상태인지 귀로 구분되지 않는다.
- 필요한 형태: 보스 계층 4종(void·teal·apricot·pale)별 attack 상승음과 death 붕괴음. WAV 0.6초 이하.
- 기존 후보·재사용 경로: `scripts/generate_sfx_parry.py`가 같은 규격(22050Hz 모노 16비트)으로 절차 생성하므로 거기에 계층 4종을 더하면 된다. 외부 샘플·라이선스 없음.
- 코드 연결 지점: `game-combat-physics.js`의 보스 피해·처치 경로, `game-feedback.js`의 `sampleSfxCue`.
- 결정·검수 메모: 아트는 반입됐으므로 소리만 남았다. attack·death 상태 자체가 아직 재생되지 않으므로(§보스 팩 규약), 상태 재생이 붙는 시점과 함께 본다.

### [반입 완료] P1 — 관측창 밖 존재·인트로 컷신

- 화면 / 트리거: 데스크톱 타이틀 진입 전, 5점 이상 별자리 현현 완료, 월드 첫 진입 또는 첫 보스 처치의 양옆 여백.
- 플레이 목적: 모바일 비율에서 남는 양옆 공간을 단순 장식이 아닌 관측창 바깥의 심연으로 전환한다. 플레이어가 별자리를 만들수록 바깥의 무언가가 관측자를 알아본다는 서사적 불안을 남기되, 전투 조작에는 관여하지 않는다.
- 필요한 형태: 외부의 관측자 부분 실루엣/별빛 굴절 레이어, 타이틀 4비트 스토리보드, 5점 이상 별자리 반응, 모션 감소 정적 대체안. 정적/절차 표현/래스터/애니메이션의 최종 조합은 미정.
- 희망 규격·프레임: 미정. 중앙 `main`보다 뒤의 데스크톱 와이드 여백 전용이며, 모바일에서는 숨기거나 정적 배경으로 축소한다.
- 화풍·색 규칙: 새벽 관측소 픽셀 아트. 청록-잿빛 밤의 저대비 윤곽과 별이 비어 보이는 음영을 쓴다. 살구색 보상·CTA, 매끈한 3D, 네온 사이버 글리치, 전신 괴물, 명확한 촉수·고어는 금지한다.

- 필요한 형태: **물이 아니다.** 수면선도 깊이 그러데이션도 두지 않는다 — 액체가 아니라 «별빛이 담긴 은하수»다. 지금 코드가 잡아 둔 뼈대는 셋이고, 셋 다 임시다:

- 남은 셋: ① 은하수의 «결»(현재는 나선 각도 하나), ② 줄기가 닿는 순간의 튀김 — 지금은 줄기와 은하수가 서로를 모른다, ③ 걷힐 때의 방식(현재는 알파 페이드 한 겹, 「스며든다」가 아니라 「꺼진다」로 읽힌다).

- 결정·검수 메모: 선행 과제였던 도형별 연결 순서는 완료됐다. `FIGURE_SHAPES[].edges`가 실제 간선을, `figureFit()`이 실루엣과 선을 같은 변환으로 배치한다. 백조자리도 중심 별을 통과하는 십자 간선을 쓴다. 다음 자산 작업은 고유 능력이 확정된 뒤의 SFX만 대상으로 한다.
