# Prism Breakers Bot Harness

`node bot/run-bot.mjs`로 실행한다. 현재 결과는 자동으로 `bot/latest-report.json`에 기록하고 표준 출력에도 보여 준다.

`runtime-harness.mjs`는 DOM·Canvas·오디오를 무해한 대역으로 바꾼 VM에서, 브라우저와 같은 ordered classic scripts와 `update(1/60)` → `updateSpecial(1/60)` → `updateFeedback(1/60)`을 직접 실행한다. 따라서 물리·충돌·패링·별자리·각성·보스 피해는 별도 근사 모델이 아니라 현재 런타임 경로를 지난다.

기본 스윕은 기믹 없는 전용 전장, 5발, 고정 파티 2명(샛별·미리내) / 3명(+윤슬) / 4명(+별하), 보스 체력 180·260·340·420, 시드 4개, `direct`와 `contact` 두 입력 정책이다. `contact`는 가까워지는 별지기에 공명 입력을 시도하고, `direct`는 보스를 곧장 노린다. 실행 보고서는 클리어·잔여 체력·발사 수·패링·노드·직격 수를 남긴다.

`runPlainArena({ steer: true })`는 발사당 1회의 좌·우 궤도 전환을 포함한 실험 케이스도 실행할 수 있다. 기본 수치 보고서에서는 전환 시점 자체가 플레이 전략이므로 임의 자동 전환을 점수에 섞지 않는다.

`runCampaignStage({ campaignIndex, partySize, policy, seed })`는 실제 캠페인 데이터의 한 스테이지를 같은 런타임 경로로 실행한다. 1-1도 전투 판정만을 위해 튜토리얼 불멸을 끄고 실행한다. 월드 HP 곡선과 시작 배치를 조정할 때 이 함수를 조합·경로·시드 스윕으로 넓힌다.

한계: 렌더·브라우저 포인터 전달·체감 타이밍은 측정하지 않는다. 고정 배치·고정 파티의 결과는 파티 인원만의 순수한 힘이 아니므로, 2→3→4 해금이나 보스 체력 확정에는 이후 파티 조합·발사 경로 스윕과 실기 검증을 함께 사용한다. 이전 근사 모델 `prism-sim.mjs`와 그 역사적 결과는 보관만 한다.
